# Unresolved Rich-Marker Removal Design

## Goal

Prevent model-invented rich-item identifiers from producing visible
`rich item ... is unavailable` captions while preserving the model's freedom to
choose whether and where genuinely available rich items improve an answer.

## Root cause

The always-on media prompt teaches every answer-producing model the
`<!--rich:<id>-->` protocol even when the turn has no rich-item inventory. The
stronger instruction to use only exact available identifiers is injected only
when candidates exist. A model can therefore infer a plausible identifier such
as `widget:dk_logo_card` on a turn that created no widget. Finalization records
the marker as `unknown_rich_item`, and the Streamlit renderer turns it into the
visible unavailable caption.

## Scope

Remove the unconditional marker instruction and expose marker syntax only in
the existing dynamic inventory block. Add deterministic reconciliation at the
final response boundary so prompt noncompliance cannot leak unresolved markers
into newly persisted content. Stop rendering a visible unavailable caption for
historical or malformed messages.

Keep unchanged:

- model choice over whether and where to place an item from the current turn's
  bounded inventory;
- exact rich-item identifiers generated by tools and backend services;
- typed rich-item validation, selected-only image persistence, automatic image
  placement, and remote-image externalization;
- pending placeholders during an active stream, because the matching upsert may
  still arrive; and
- fenced, indented, and inline-code examples containing marker syntax.

No persisted message rows are rewritten.

## Prompt behavior

The always-on media capability text may recommend image search and explain when
visuals are useful, but it must not expose rich-marker syntax or encourage the
model to infer identifiers. Marker syntax and the `Never invent an ID` rule are
delivered together only when `build_rich_response_guidance()` has constructed a
non-empty inventory for the current turn.

This keeps the interface data-driven: there is no list of allowed widget names,
image types, brands, or domains in the prompt. The inventory remains the single
source of exact identifiers, and the model retains freedom to omit an item or
place it near the prose it supports.

## Finalization behavior

After `build_bot_metadata()` creates the authoritative public registry and
before remote-image externalization or persistence, reconcile body markers
against `metadata.rich_items`:

1. Leave every marker whose exact identifier exists in the finalized registry.
2. Remove every unresolved marker outside fenced, indented, and inline code.
3. Preserve surrounding Markdown and normalize only blank lines created by the
   removal.
4. Recalculate `rich_reference_warnings` against the cleaned content so
   persisted metadata describes the persisted body.
5. Log one bounded warning for the reconciliation event without logging answer
   text, URLs, or user data.

Both completed-workflow persistence paths use the same reconciliation helper.
Remote-image externalization remains later in the pipeline and can continue to
remove a valid image marker if protected-reference registration fails.

## Rendering behavior

The internal `unavailable` segment remains because it distinguishes a marker
waiting for a stream upsert from ordinary Markdown. During an active stream it
continues to render the existing pending placeholder. Once a message is final,
the Streamlit renderer emits nothing for an unresolved segment. Persisted
history uses the same silent behavior, which repairs the visible symptom for old
rows without mutating the database.

## Testing

Tests must prove that:

- the always-on media prompt contains no rich-marker protocol;
- dynamic guidance includes marker syntax and exact-ID constraints only with a
  real inventory;
- reconciliation removes an invented widget marker and clears stale reference
  warnings;
- reconciliation preserves valid markers and marker examples in fenced,
  indented, and inline code;
- both normal completion and resume persistence paths invoke reconciliation;
- final and historical rendering emits no unavailable caption;
- active streaming still shows a pending placeholder before an upsert; and
- existing rich-response, placement, streaming, and message-service tests remain
  green.

## Documentation

Update the current rich-response and frontend rendering contracts to state that
new unresolved markers are removed during finalization and old unresolved
markers render silently. Historical design and implementation plans remain
unchanged as records of prior decisions.
